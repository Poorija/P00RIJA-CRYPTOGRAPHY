# P00RIJA Cryptography 2.35.0

Offline-first encryption suite and end-to-end encrypted messenger. Everything
runs on the device: keys are generated by the platform's own CSPRNG through Web
Crypto and never leave it, and the relay only ever sees sealed envelopes.

This release is about three things that a private messenger needs and this one
did not have: a way to be woken on Android without Google in the path, a way to
be told a newer version exists, and a relay that can be closed to strangers.

---

## Waking an Android phone without Google

Android's WebView implements service workers but does not expose the Push API
to them — that is a Chrome feature, not a WebView one. So the browser build's
push route simply does not exist inside the native shell, and the native
Android app could not be woken at all.

**UnifiedPush** fills that gap without FCM. A distributor app you installed and
chose holds the socket, and the relay posts to the URL it hands out. Installed
distributors are listed for you, never picked for you: which app holds a socket
to which server on your behalf is exactly the decision this feature exists to
hand back.

The notification says a message is waiting and nothing else. The relay does not
know who sent it and neither does the phone, and it is posted so that a lock
screen shows nothing at all.

**A fallback, for a phone with no distributor.** A fifteen-minute look, which is
the platform's floor and under Doze rather less. It is the worse answer and it
is off until you turn it on, because it costs a token at rest and a request on a
schedule — a traffic pattern where there was none.

## Biometric unlock on Android and iOS

The master password can now be kept under a key that lives in the **Android
Keystore** or the **iOS Keychain**, released only after a face or a finger. The
refusal is the operating system's, not the app's: the ciphertext sits in app
storage precisely because it is worthless without a key that never leaves the
secure element.

Enrolling a new face or finger invalidates what was stored, and the password
has to be entered once more. That is deliberate — a new finger is a new person
until the owner says otherwise.

Conversation and tab locks open with biometrics too, on both platforms.

## Being told a newer version exists

About gains a check, and the native builds ask once a day at launch. The dialog
names the version you are on, the one that is out, and what the release notes
say — and it takes no for an answer.

Accepting downloads nothing inside the app. It opens the file built for your
machine in your browser, and you install it. Neither phone platform lets an app
replace itself, and on the desktop a self-updater that fetches and runs a binary
is a remote code execution channel into a cryptography app.

The check is named in About and can be turned off. It is the one request this
app makes without being asked, it carries no identifier, and a suite that says
"no telemetry" should tell you about it rather than let you find it in a packet
capture.

The browser and Home Screen builds are excluded: the service worker already
updates them.

## A relay that can be closed

Suspension and kicking are deny lists — everybody is welcome until named. The
new **allowlist** is the other way round: nobody connects unless you have put
their fingerprint on it.

It is keyed on the identity fingerprint, which is derived from the public key,
so generating a new key produces a new stranger rather than a way around the
door. On a deny list, rotation always is.

Closing the door on an empty list is refused — it would lock you out of your own
relay, and the way back in is a text editor over SSH.

## Updating a server

`scripts/update-server.sh` compares what is installed against the newest
published release, prints what that release says it changed, and asks before
doing anything. It keeps `.env`, `certs/`, `data/` and everything else the
install created, replacing only the code, and takes a snapshot first.

## Security

Three issues were found and fixed while building the above. Two of them were
introduced by this release's own work and caught before it shipped; the third
predates it.

**A push endpoint could aim the relay at its own network.** `/push/subscribe`
takes no credentials — a device has to register before it has any — so the
endpoint URL was attacker-controlled by design. Anyone able to reach the relay
could point it at a cloud metadata address and have it knock from inside the
perimeter. The host is now resolved and judged before the row is stored and
again before every send, and redirects are refused rather than followed.

**A subscription did not have to belong to the fingerprint it named.** Anyone
could register their endpoint against somebody else's fingerprint and be told
every time that person received a message — who is talking to whom and when,
which is the one thing encryption cannot hide. Five such rows also pushed the
real device out of a list capped at five. Subscribing now requires proving the
identity key, through the same challenge the presence socket already used. This
one predates UnifiedPush and affected the browser path too.

**Credentials were written world-readable.** The token and subscription stores
landed 0644 under the default umask; on a server with more than one account
that is every other account. Both now go through a writer that opens a
temporary file 0600 and renames it over the target.

Every one of these has a test that exercises the refusal. An untested security
control is a comment.

## Platforms

| | |
|---|---|
| macOS | Apple Silicon and Intel, universal disk image |
| Windows | x64 and ARM64 installers |
| Linux | deb, rpm and portable tarballs, x86_64 and ARM64 |
| Android | universal APK and AAB |
| Browser / PWA | installable from the site, updates itself |

The desktop, Android and browser builds are verified. **iOS is written and
compiles but has not been run on a device**, and the release carries no iOS
artefact: without a paid Apple Developer account there is nothing to
side-load, and the Home Screen web app is the supported route there.

## Installing

The packages are not signed by Apple, Google or Microsoft. `INSTALL.md`
explains what each system will say the first time and how to get past it.
